# Contributing to ApInsight

Contributions to ApInsight are welcome.

## Reporting bugs and requesting features

Please use the GitHub issue tracker to report bugs, suggest improvements, or request new features.

When reporting a bug, please include where possible:

- the ApInsight version or release used;
- operating system and Python version;
- a description of the problem and the steps needed to reproduce it;
- the complete error message or traceback;
- relevant information about the GPR dataset or file format.

Please do not upload research data that cannot be shared publicly.

## Code contributions

Code contributions can be submitted through pull requests.

Before submitting a pull request:

1. briefly describe the proposed change in an issue when the change is substantial;
2. keep changes focused on a specific problem or feature;
3. run the automated tests with:

   `python -m pytest`

4. add or update tests where appropriate for new numerical or data-processing functionality;
5. update documentation where the behaviour or user workflow changes.

Pull requests are automatically tested using GitHub Actions.

## Development and maintenance

ApInsight is currently developed and maintained by Erich Nau.

The software was originally developed for archaeological GPR analysis at the Norwegian Institute for Cultural Heritage Research (NIKU). Development is driven primarily by research requirements, archaeological applications, and feedback from users.

Issues and contributions are reviewed as time and project resources permit. No specific response or implementation time can be guaranteed.
